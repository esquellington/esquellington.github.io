...specifically, it sucks too little error per iteration, making it very
inefficient for rigid impact problems.

* Problem

We want to solve a perfectly inelastic impact of a rigid body B moving
towards a rigid body A that is initially resting on the ground C. A is
sandwiched between B and C.

(TODO sketch: ground plance C, body A, body B, positive vel dir downwards)

With the sign convention that velocities are positive towards ground
C, the pre-collision initial conditions are:

\[ V_a(0) = 0 ,\quad V_b(0) > 0 ,\quad V_c = 0 \]

Masses are arbitrary, but we'll assume $m_a \leq m_b$.

** Collision Constraints

Collisions introduce the following inequality constraints on relative
post-collision velocities $V_{ij}=V_i-V_j$.

\[V_{ca}^* \geq 0 ,\quad V_{ab}^* \geq 0 \]

** Solution

Due to inelasticity, A vs B ad B vs C will never bounce. B will
transfer momentum to A, that will transfer it to C, that will absorb
it completely. Velocities will never change sign. The "intuitive"
solution for post-collision velocities is
\[V_a^* = 0 ,\quad V_b^* = 0\]

This is the simplest collision problem involving 2 dynamic bodies
A,B. We'll see that solving it numerically with sequential impulses
needs a number of iterations that grows linearly with the mass ratio
$\frac{m_b}{m_a}$.

* Inelastic collision response

The pairwise instantaneous inelastic collision response for AB is
\begin{align*}
V_a^+ &= V_a^- - V_{ab} w_a \\
V_b^+ &= V_b^- + V_{ab} w_b
\end{align*}

where
\[
  w_a = \frac{\frac{1}{m_a}}{\frac{1}{m_a} + \frac{1}{m_b}}
  ,\quad
  w_b = \frac{\frac{1}{m_b}}{\frac{1}{m_a} + \frac{1}{m_b}} = 1-w_a
\]

* Sequential Impulses

Sequential impulses solves the problem as a sequence of local
collision responses between pairs of bodies that is iterated until
convergence. Each iteration $k$ we'll solve collisions AC and AB:

- Solve $V_{ca}^{(k)} \geq 0$, resulting in $V_a^{(k)} = 0$
- Solve $V_{ab}^{(k)} \geq 0$, with $V_{ab}^{(k)} = -V_b^{(k)}$ because $V_a^{(k)} = 0$

We can assume all collision constraints are Active, due to compressive
init state and inelssticity, so all constraint inequalities become
equalities.

We have the recurrence:
\begin{align*}
V_b^{(k)} &= V_b^{(k-1)} - V_b^{(k-1)} w_b \\
          &= V_b^{(k-1)} w_a  \quad (\leftarrow w_a=1-w_b)\\
          &= V_b^{(0)} w_a^{k}
\end{align*}

The mass ratio $\xi = \frac{m_b}{m_a}$ can also be written as
$\frac{w_a}{1-w_a}$, and therefore the velocity changes on A,B do not
depend on their individual masses, only on their mass ratio, with $w_a
= \frac{\xi}{\xi+1}$ (derivation omitted).

** How many iterations do we need?
Due to inelasticity we know that in the limit $V_b^{(\infty)} = 0$. In
practice we'll iterate until error drops below an absolute threshold
$V_b^{(k^*)} < \epsilon$, represented by the horizontal line in the
previous plot.

We can assume $k^*$ is real and isolate it taking $\log$ on both sides
of $V_b^{(0)} w_a^{k} = \epsilon$ to obtain:

\[ k^* = \frac{\log(\epsilon/V_b^{(0)})}{\log(w_a)} = \frac{\log(\epsilon/V_b^{(0)})}{\log(\xi/(\xi+1))} \]

We plot $k^*(\xi)$ with the same parameters as above.

This looks surprisingly linear... and it *almost* is!

We can show that $\log(\xi/(\xi+1))$ is very close to $-1/(\xi+1)$ for
$\xi>2$ (see [[Linear Approx]]), so we can approximate $k^*(\xi)$
as
\[ k^* \approx -\log(\epsilon/V_b^{(0)}) (\xi+1)\]

From this linear approximation we can see that the slope $-\log(\epsilon/V_b^{(0)})$ changes very
moderately with both $V_b^{(0)}$ and $\epsilon$, and that the
parameter that affects $k^{*}$ the most is the mass ratio $\xi$.

  int main( int argc, char** argv )
  {
      const float xi(10.0f), wa(xi/(xi+1));
      const float eps(1e-3f);
      const int K(100);
      float Va(0), Vb(10);
      int k(0);
      printf("k V_a V_b");
      while( k < K && Vb > eps ) //iterate until convergence
      {
          if( k%5 == 0 ) printf("\n%d %2.4f %2.4f",k,Va,Vb);
          Va = 0.0f; //solve AC
          float Vab(Va-Vb); //solve AB
          Va -= Vab * wa;
          Vb += Vab * (1-wa);
          k++;
      }
      printf("\n%d %2.4f %2.4f",k,Va,Vb);
      return 0;
  }

* TODO [#A] Conclusions

Converging below a given *absolute* precision $\epsilon$ requires
proportionally more iterations as $\xi$ grows. Impact speed and
precision threshold do not matter much, compared to mass ratio, or
number of bodies.

This makes Sequential Impulses really inefficient for impact
problems. It's not so bad for persistent contact problems, where
impulses can be warmstarted and improved incrementally over multiple
timesteps, but that's not an option on the first impact timestep, as
no previous solution exists.

SI is very easy to implement, that's why it's so popular, but
(etc...). Can we do better somehow, without losing all simplicity?

#+NAME: GSimulateStack1D
#+BEGIN_SRC C++
  template <unsigned int N>
  void GSimulateStack1D( float xi, float V0, float G, //massratio, vel, grav
                         int T, float dt, //steps and timestep
                         float epsilon, int K, //precision and iterations
                         bool bWarmstart, float ws_decay01 ) //warmstarting
  {
      const float wa(xi/(xi+1));
      float V[N] = {}; V[N-1] = V0;
      float cached_Vab[N] = {};
      printf("t k");
      for( int n=0; n<N; n++ )
          printf(" V[%d]", n);
      int tk(0); //total iter across timesteps
      for( int t=0; t<T; t++ ) //T frames
      {
          // Integrate t->t+dt
          for( int n=1; n<N; n++ )
              V[n] += dt*G;
          int k(0); //per-step iter

          // TODO Apply warmstarting, but only after contacts applied
          // their 2nd impulse, not 1st (persisted for >1 steps, save on
          // 2nd step, apply on 3rd)
          if( bWarmstart && t>1 )
          {
              for( int n=1; n<N; n++ )
              {
                  float wa_n( n==1 ? 0.0f : wa ); //B[0] is static
                  V[n-1] -= cached_Vab[n] * wa_n;
                  V[n] += cached_Vab[n] * (1-wa_n);
                  cached_Vab[n] *= ws_decay01;
              }
          }
          // Solve/refine constraints after warmstarting
          while( k < K && V[N-1] > epsilon )
          {
              if( k%10 == 0 )
              {
                  printf("\n%d %d",t,tk);
                  for( int n=0; n<N; n++ )
                      printf(" %2.4f",V[n]);
              }
              V[0] = 0.0f; //solve AC
              for( int n=1; n<N; n++ )
              {
                  float Vab( V[n-1] - V[n] ); //solve AB
                  float wa_n( n==1 ? 0.0f : wa ); //B[0] is static
                  // req separating contact (TODO not sure if correct,
                  // we should clamp total not per-iter)
                  if( Vab > 0.0f )
                      Vab = 0.0f;

                  V[n-1] -= Vab * wa_n;
                  V[n] += Vab * (1-wa_n);

                  // Update warmstarting after 1st step
                  if( bWarmstart && t>0 )
                      cached_Vab[n] += Vab;
              }
              k++;
              tk++;
          }
          printf("\n%d %d",t,tk);
          for( int n=0; n<N; n++ )
              printf(" %2.4f",V[n]);
      }
  }
#+END_SRC

** TODO Warmstart theory
WS is not a “guess” of the actual solution, it’s an “assumption” of
the solution that cannot be fully undone, and that can change it
completely.

It applies impulses indistinguishable from external magic forces that
change the problem, as opposed to a guess in ConjGrad or similar,
that starts search from solution “closer” to that solution, but does
not change the problem or solution to it (unless it perturbs it to
find a different local minima if problem is not convex) This same
issue would happen with XPBD or any other GS-like solver where WS
values need to be applied in the same way PGS would apply local steps
towards the solution, WS tries to skip these local steps, assuming
they’d repeat exactly, so it can comtinue from there

It’s practical, but it’s objectively wrong. Some bad cases can be
avoided with heuristics, but not all I suspect

The fact that this is not improved by substepping is a big red flag, actually.

Compare with:
- direct solve preconditioning
- iterative solve guessing (CG)
- AVBD “warmstarting”
Show they converge to same value if “guess” is perturbed, just slower/faster
